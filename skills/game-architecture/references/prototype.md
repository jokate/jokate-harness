# 프로토타입 — 버리는 코드로 질문 하나에 답한다

> 일부를 Matt Pocock 의 skills(`prototype`, MIT, Copyright (c) 2026 Matt Pocock)에서 빌려 게임 프로젝트에 맞게 고쳤다.
> 라이선스: `docs/third_party/mattpocock-skills-LICENSE` · 원본 추적: `docs/UPSTREAM.md`.

## 언제 쓰나 · 쓰지 않나

- 쓴다: 선택지나 질문이 "느낌이 맞나 / 예외를 감당하나"에 달려 있고, 읽어서는 못 가릴 때.
  - 콤보 취소 창 · 선입력 버퍼 · 버프 중첩 모델이 예외 입력까지 버티나
  - 발사 간격 · 히트스톱이 손에 맞나, HUD 배치는 어느 쪽이 읽히나
- 쓰지 않는다: 코드를 읽거나 테스트를 돌리면 답이 나올 때. 사실은 직접 찾는다.
- 쓰지 않는다: 값 하나 고르는 일. 수치는 CVar 로 열어 두고 만지게 한다.

## 흐름 — 동의 뒤에만 만든다

- 프로토타입은 질문 표의 한 행으로 제안한다. 추천 칸에 "예 — 만들어 보는 쪽이 읽는 것보다 싸다" 같은 이유 한 구절.

| # | 질문 | 갈래 | 추천 | 답에 따라 바뀌는 것 |
|---|---|---|---|---|
| 2 | 선입력 버퍼 규칙을 HTML 로 먼저 돌려 볼까? | 예 / 아니오 | 예 — 취소 창 예외가 표로는 안 보인다 | 예면 B·C 의 전이 표가 확정된다 |

- 사용자가 "예"라고 하기 전에는 만들지 않는다. 만든 뒤에도 고르는 것은 사용자다.
- 프로토타입 하나는 질문 하나다. 질문을 화면 맨 위(HTML) · 파일 머리(코드)에 한 줄로 적는다.

## 규칙 · 상태 — HTML 한 장

- 파일 하나. 프레임워크 · CDN · 서버가 없다. 더블클릭으로 열리고 오프라인에서 돈다.
- 다크 모드는 `prefers-color-scheme` 로 따른다. 라벨은 기획 언어다("약공격 입력", "0.1초 경과", "피격"). 기획자가 혼자 눌러 본다.
- 규칙 모듈을 `<script>` 안에 순수하게 따로 둔다. DOM 을 만지지 않는다.
  - 이산 사건이면 `(state, action) => state`, "지금 가능한 입력"이 질문이면 상태 머신.
  - 시간은 숨은 시계가 아니라 액션이다(`경과(dt)` 버튼). 취소 창 · 버퍼 만료가 매번 같게 재생된다.
- 화면 순서: 질문 → 현재 상태 → 자유 버튼 → 시나리오 탭.
  - 상태 패널은 이름 붙은 칸이다(JSON 덤프 금지). 클릭마다 다시 그리고 방금 바뀐 칸을 강조한다.
  - 자유 버튼은 항상 눌린다. 막혀야 하는 입력은 거절 사유를 상태 패널에 보인다.
- 시나리오 탭은 셋 이상이다: 정상 경로 · 까다로운 예외 · 막혀야 하는 것.
  - 탭마다 상황 설명, 그 아래에 눌러야 할 버튼을 순서대로 둔다. 시작할 때 초기 상태로 되돌린다.
- 실제 코드로 올리는 것은 JS 가 아니라 검증된 전이 표 · 규칙 표다.
  - 올릴 곳: C++ 상태 머신 · DataTable/DataAsset · StateTree · ScriptableObject
- 저장: `<프로젝트>/Saved/ClaudeArch/proto/<YYYYMMDD>-<주제>.html` (Unity 는 `Library/ClaudeArch/proto/`). VCS 무시 폴더다.

## 느낌 · 화면 — 엔진 안에서

- 히트스톱 · 발사 간격 · HUD 는 엔진에서만 느껴진다. 그레이박스 테스트 맵이나 기존 레벨에서 돌린다.
- 기존 레벨이 먼저다. 실제 밀도 옆에서 봐야 한다.
- 변형은 기본 3개, 최대 5개다. 구조가 달라야 한다.
  - HUD: 조준점 옆 링 / 화면 모서리 막대 / 캐릭터 발밑 월드 표시
  - 히트스톱: 전역 정지 / 피격자만 정지 / 짧은 슬로모 + 카메라 흔들림
- 숫자만 다른 것은 변형이 아니다. 숫자는 CVar 로 열어 라이브로 만진다.

| 필요 | Unreal | Unity |
|---|---|---|
| 변형 전환 | `TAutoConsoleVariable` `proto.<주제>.Variant` 0/1/2 | 디버그 키 또는 static 토글 |
| 현재 변형 · 핵심 상태 표시 | `GEngine->AddOnScreenDebugMessage`(키 고정), 디버그 HUD | `OnGUI` |
| 수치 노출 | `proto.<주제>.<이름>` CVar | static 필드 + `OnGUI` 슬라이더 |
| 버릴 코드 표시 | `Content/Prototype/<주제>/`, `Source/<모듈>/Prototype/`, `PROTO_` 접두 | `Prototype/` 폴더, `PROTO_` 접두 |
| 출하 제외 | `#if !UE_BUILD_SHIPPING` 또는 에디터 전용 | `#if UNITY_EDITOR \|\| DEVELOPMENT_BUILD` |

- 실행은 테스트 맵 하나 또는 콘솔 명령 한 줄이다. 넘길 때 맵 · 명령 · 변형 번호를 한 줄로 알린다.

## 둘 다 지킬 것

- 처음부터 버릴 코드다. 이름과 폴더로 드러낸다.
- 세이브 게임을 쓰지 않는다. 메모리에 둔다. 저장이 질문일 때만 `PROTO_` 이름의 임시 슬롯을 쓴다.
- 다듬지 않는다. 테스트 · 추상화를 넣지 않고, 오류 처리는 돌아가는 데 필요한 만큼만 한다.
- 상태를 보인다: 액션마다(HTML), 변형을 바꿀 때마다(엔진).

## 끝나면

- '근거' 절의 '확인한 사실' 표에 한 행으로 판정을 남긴다: 질문 · 결정 · 프로토타입 위치, 확신은 확인.
- 실제 코드에는 검증된 결정만 올린다. 프로토타입 코드는 다시 쓴다.
- 메인 계통에서 치운다.
  - Git: 버리는 브랜치에 남기고 main 에는 판정만 둔다.
  - SVN · Perforce: 올리지 않는다. 작업 사본에서 지운다.

## 하지 말 것

- 실제 세이브 · 온라인 · 결제 · 업적 SDK 에 연결하기. 스텁이나 메모리를 쓴다.
- "나중을 위해" 일반화하기. 질문 하나에만 답한다.
- 프로토타입 BP · C++ 를 그대로 production 에 올리기.
- 숫자만 다른 변형 만들기, 변형끼리 레이아웃을 공유하기.
- 규칙 모듈이 DOM 을 만지게 하기. 전이 표를 뽑아낼 수 없다.
- 출하 제외 가드 없이 `Prototype/` 을 두기.
- 판정을 남기지 않고 지우기. 다음 사람이 같은 질문을 다시 만든다.
