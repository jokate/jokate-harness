# 테스트 문서 템플릿

기능 하나에 한 장. 구현 전에 1~3 을 채우고, 구현 후 4 를 채운다.

```markdown
# <기능 이름> — 검증

## 1. 완료 기준
- [ ] <관찰 가능한 결과 1> (예: 적중 시 대상 HP 가 공식대로 감소)
- [ ] <관찰 가능한 결과 2>
- [ ] <하지 말아야 할 것> (예: 무적 상태에서는 감소하지 않음)

## 2. 자동 테스트
| 테스트 | 종류 | 대상 | 파일 |
|---|---|---|---|
| <Game.Damage.Formula> | 단위 | 피해 공식 경계값 | <경로> |
| <Game.Damage.HitApplies> | 기능 | 스폰 → 적중 → HP | <경로> |

실행: `<명령>`

## 3. 수동 체크리스트
| # | 절차 | 기대 | 결과 | 확인자 |
|---|---|---|---|---|
| 1 | <맵>에서 <캐릭터>로 <행동> | <무엇이 보여야 하나> | | |

## 4. 결과 (<날짜>)
- 자동: <통과 N / 실패 M> — 실패: <이름>
- 수동: <확인한 항목 번호>
- 상태: 검증됨(자동) / 검증됨(수동) / 검증 안 됨 — <이유>
```

## 작성 규칙

- 완료 기준은 **관찰 가능한 결과**로. "잘 동작한다", "자연스럽다"는 기준이 아니다.
- 경계값과 금지 조건(하지 말아야 할 것)을 최소 하나씩.
- 수동 항목은 다른 사람이 읽고 그대로 따라 할 수 있게 — 맵, 캐릭터, 입력, 기대 결과.
- 사내 문서 도구에 옮길 때도 이 네 절 구조를 유지한다.
