# diff-proto — 시안의 바뀐 부분을 확인받는다

## 순서

1. 볼 변경을 정한다.
   - 인자가 '무엇을 짜라' 면 시안 코드를 작업 사본에 쓴다. 시안은 질문 하나에 답하는 가장 작은 변경이다. 다듬지 않는다. 커밋하지 않는다.
   - '이미 바뀐 것을 보여 달라' 면 쓰지 않는다. 지금 작업 사본의 변경을 그대로 본다.
2. diff 를 읽는다. git 은 `git diff HEAD` 와 새 파일, svn 은 `svn diff`.
   파일마다 조각(`@@` 한 덩어리)을 위에서부터 1번으로 센다.
3. 이야기 JSON 을 쓴다. 꼴은 [references/story-sample.json](references/story-sample.json) 그대로다.
   - 위치: `<프로젝트>/Saved/ClaudeArch/decide/<YYYYMMDD>-<주제>-diff.json` (Unity 는 `Library/ClaudeArch/decide/`, 그 밖은 `<프로젝트>/.claude/decide/`).
   - 묶음은 뜻이 같은 변경이다. 파일 순서가 아니라 읽는 순서로 놓는다. 왜 바꿨는지 드러나는 묶음이 먼저, 따라 바뀐 것은 뒤.
   - `title` 은 결론 문장이다("만료된 입력은 건너뛴다").
   - `why` 는 무엇이 문제였나 한 줄. `look` 은 사용자가 눈으로 확인할 것 한 줄.
   - `risk` 는 높음 · 중간 · 낮음. 높음은 동작이 바뀌는 곳, 낮음은 이름 · 포맷 · 따라 바뀐 선언.
   - `match` 는 그 묶음의 조각이다: `"경로"`(파일 전부) · `"경로#2"`(둘째 조각) · `"경로#1-3"` · `"Source/*.h"`.
   - 묶음은 7개 이하. 기계적인 변경은 한 묶음으로 모은다.
4. 점검한다.
   `python ~/.claude/skills/selection/scripts/diffdoc.py <이야기.json> --path <저장소> --check`
   - `이야기 오류` 는 diff 에 없는 것을 가리켰다는 뜻이다. 이야기를 고친다.
   - `묶이지 않은 것` 이 0 이 되게 한다. 남기면 페이지 끝에 '묶이지 않은 변경' 으로 그대로 나온다.
   - svn 에 올리지 않은 새 파일은 `--add <파일>` 로 준다. 작업 사본을 건드리지 않은 시안은 `--patch <파일.diff>` 로 준다.
5. 띄운다. **백그라운드로 돌린다.** `--check` 만 빼고 같은 명령이다.
   - 사용자는 묶음마다 '확인함' 을 누르고 메모를 적는다. 나란히 보기와 한 줄로 보기를 바꿀 수 있다.
   - Enter 로 보내면 명령이 검토 결과를 찍고 끝난다. 탭은 스스로 닫히고 이야기 파일은 지워진다. HTML 파일은 남지 않는다.
   - 명령이 끝났다는 알림이 오면 그 출력을 읽는다. 답이 거기 있다.
6. 결과를 읽고 이어 간다.
   - 메모가 달린 묶음은 지적이다. 고치고 3~5를 다시 한다.
   - `안 함` 인 묶음은 확인받지 못한 것이다. 확인받은 것으로 쓰지 않는다.
   - 전부 확인이면 다음 단계로 간다. 시안을 본 구현으로 올릴 때는 다듬어 다시 쓴다.

## 규칙

- 코드는 diff 에서만 온다. 페이지에 내가 옮겨 적은 코드를 넣지 않는다. 내가 쓰는 것은 왜와 볼 것뿐이다.
- 한 줄에 사실 하나. 묶음 제목에 파일 이름 · 함수 이름을 늘어놓지 않는다.
- 바뀐 줄이 3000줄을 넘으면 `--path` 를 하위 폴더로 좁혀 나눠 낸다.
- 서버를 못 띄우면 `/selection` 의 '서버를 못 띄울 때' 와 같다. 이 경우 diff 를 대화에 표로 요약해 낸다.
