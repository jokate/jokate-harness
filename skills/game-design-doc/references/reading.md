# 기획서 유형별 읽는 법

## 목차
- 시스템 기획
- 캐릭터·스킬 킷
- 밸런스 표
- UI 플로우
- 레벨·콘텐츠 기획
- 사내 문서 형식

## 시스템 기획 (전투, 성장, 경제, CC …)

먼저 찾을 것: 규칙의 **적용 범위**(누구에게), **상태 전이**(언제 켜지고 꺼지나), **다른 시스템과의 상호작용**.
흔한 빈칸: 중첩·갱신 규칙, 동시 발동 우선순위, 취소·사망·맵 이동 시 정리, 서버/클라 판정 주체.
구조 판단 신호: 같은 규칙이 여러 캐릭터·콘텐츠에 "공용"으로 적혀 있으면 공통 축 후보 → `game-architecture`.

## 캐릭터·스킬 킷

먼저 찾을 것: 입력 → 발동 조건 → 효과 → 쿨타임·자원 → 상호작용(다른 스킬 강화·취소).
흔한 빈칸: 입력 버퍼·선입력, 이동 중 발동 가능 여부, 피격 시 취소, 애니메이션 캔슬 타이밍, 판정 프레임.
구현 대응 요령: 기존 캐릭터와 같은 축(투사체, 범위 판정, 버프)을 먼저 찾는다 — 새로 만들 것과 재사용할 것을 가른다.

## 밸런스 표 (엑셀·CSV)

먼저 찾을 것: 열의 단위, 키(ID) 규칙, 공식(수식 셀)이 있는지.
흔한 빈칸: 단위(초/프레임, %/소수), 반올림 규칙, 레벨 구간 밖의 값.
구현 대응 요령: 표 구조가 엔진 데이터(DataTable 행 구조체, ScriptableObject 필드)와 1:1 인지 본다. 1:1 이 아니면 임포트 변환이 필요하다는 것 자체가 보고 대상.

## UI 플로우

먼저 찾을 것: 화면 목록과 전이, 각 화면의 입력·뒤로가기, 데이터 출처(어떤 시스템의 값을 보여주나).
흔한 빈칸: 로딩·실패·빈 상태 화면, 팝업 중첩, 게임패드 포커스 이동.

## 레벨·콘텐츠 기획

먼저 찾을 것: 목표·실패 조건, 스폰 규칙(언제·어디서·몇), 스크립트 이벤트 트리거.
흔한 빈칸: 재시작·체크포인트 시 상태 복원, 멀티플레이 인원 스케일링.
구현 대응 요령: 레벨 스크립트(BP)·시퀀스 안에 있는 로직은 소스로 안 보인다 → "확인 불가"로 두고 MCP 조회.

## 사내 문서 형식

| 형식 | 받는 법 |
|---|---|
| Confluence | 페이지 내보내기(Word/PDF) 또는 본문 복사 → md 로 저장 |
| 엑셀 | CSV 로 저장, 시트마다 파일 하나 |
| PPT | PDF 로 내보내기 |
| 위키·노션 | Markdown 내보내기 |

받은 파일은 프로젝트 문서 폴더에 두면 `gq.py` 인덱스에 잡힌다 (md 만. CSV·PDF 는 직접 읽는다).
